# 領収書统一半自动流程

部署到 Google Apps Script 的文件：

- `apps-script/ReceiptUnifiedFlow.gs`

仓库中的 `ReceiptSemiAutoAppend.gs` 和 `ReceiptMailDraftsDynamic.gs` 是维护用拆分源码，不需要分别复制到表格。

## 资料读取顺序

每个 Game ID 独立判断：

1. 优先读取 `領収書申請入力` 中的手写资料。
2. 手写行缺少姓名、邮箱或宛名时，从 `フォームの回答 1` 补齐。
3. 没有手写行时，直接使用フォーム回答。
4. 两边都无法取得必要资料时，在 `CHECK_REPORT` 报错且不生成该笔领收书。

因此，同一套脚本既可以用于有フォーム回答的表格，也可以用于完全手写的追加表格。

## 初次设置

1. 将 `ReceiptUnifiedFlow.gs` 添加到 Spreadsheet 的 Apps Script 项目。
2. 旧普通版的 `ReceiptFormPwUnifiedFlow.gs` 不再同时部署，避免菜单和 `onOpen` 冲突。
3. 手动执行一次 `setupReceiptSemiAutoAppend` 并完成授权。
4. 打开菜单 `領収書半自動 > 領収書設定を開く`。
5. 在 `PNG DriveフォルダURL` 的设置值中填写 PNG 所在 Drive 文件夹 URL。
6. 如果存在多个 `CSV書き出しシート`，在 `CSV書き出しシート名` 的下拉框选择本次使用的表。

设置会准备：

- `領収書申請入力`
- `書き出しデータ`
- `CHECK_REPORT`
- `領収書半自動_RUN_LOG`
- `領収書設定`

现有 `メール送信` 或 `メール送信一覧` 会自动识别，不会自动重建。

## 每次操作

1. 将 TSV 粘贴到 `PW TSVショウ用`。
2. 需要覆盖フォーム资料或没有フォーム回答时，在 `領収書申請入力` 填写资料。
3. 执行 `1. PW TSV→トナメ抜き出し チェック` 并查看异常。
4. 执行 `1. PW TSV→トナメ抜き出し 実行`，只将本次资料追加到 `トナメ抜き出し`。
5. 按原流程处理 CSV/`書き出しデータ`，并在 Illustrator 生成 PNG。
6. 执行 `2. 最新トナメ行→メール送信生成`，只生成本次邮件行。
7. 将 PNG 放入设置表指定的 Drive 文件夹。
8. 执行 `最新分のGmail下書きを作成`。
9. 检查草稿后，标记 OK 并发送。

## 自动清理

`領収書設定` 中的 `下書き成功後に手入力をクリア` 默认为 `ON`。

- 只清空本次已成功生成草稿所使用的手写行。
- PNG 匹配失败或草稿生成失败的手写行会保留，方便修正后重试。
- フォーム回答、设置、检查报告和历史记录不会被清空。
- 将设置值改成 `OFF` 可停止自动清理。

## PNG 文件名

以下格式均可识别：

- `領収書_清水康平 様-13.png`
- `領収書 清水康平 様-13.png`
- `領収書　清水康平 様-13.png`

Drive 扫描只检查设置文件夹的直属文件，不递归扫描子文件夹。
